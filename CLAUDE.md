## Development Commands & Workflow

### 🚀 Local Development Setup
The project requires running the following sequence of commands for a full local development environment:

1.  **Install Dependencies:** `pnpm install` or `npm install`.
2.  **Start Environment:** `npm run dev`. This command uses `concurrently` to launch multiple services required for continuous development:
    *   The Laravel web server (`php artisan serve`).
    *   The Vue frontend Vite development server (`vite`).
    *   A background queue listener (`php artisan queue:listen`).

### 🧪 Testing & Linting
Testing involves validating both the backend business logic and the frontend components.

*   **Backend Unit/Feature Tests:** `npm run test` or `php artisan test`. This uses PHPUnit to verify API endpoints, data persistence, and core business rules (e.g., permissions policies).
*   **Linting (Code Style):** Run via `pnpm lint` which executes ESLint on Vue files, enforcing code style standards as part of the pre-commit hook.

### 🧱 Build Process
The production build is triggered by `npm run build`, which ensures both Vue TypeScript compilation and Vite's optimized asset bundling are completed. This process is critical and automatically checked via a pre-push hook.

## Key Architectural Patterns & Modules

### Activity Logging System (Critical)
*   **Persistence:** Logs are stored in the dedicated `activity_logs` table (`database/migrations/...`).
*   **Creation Flow:** The central logic resides in **`app/Support/Activity/ActivityLogger.php`**. This service is responsible for triggering and creating log entries, preferably asynchronously using **`app\Jobs\LogActivityJob.php`** to avoid blocking the main request thread.
*   **API Retrieval:** Activity logs are exposed via `routes/api.php` endpoint `/api/activity-logs`. The retrieval flow uses:
    1.  **Authorization:** Checks against **`app\Policies\ActivityLogPolicy.php`**.
    2.  **Data Shaping:** Uses **`app\Http\Resources\ActivityLogResource.php`** to ensure a consistent, consumable JSON response format for the client.

### Frontend Structure (Vue 3)
*   The admin interface is organized by feature/module (`resources/js/admin/views/*`).
*   State management relies heavily on **Pinia**. The Activity Log list view component must consume data fetched from the backend API and map it into a visible, sortable table structure.
